No kot so že povedali, v C#-u en moreš pisat metod izven classov.
In kot je Kavan povedal fora static method je da jih lahko kličeš brez instantiranega objekta ampak po imenu razreda se pravi v tvojem primeru Nothing.Main();

In to metodo pokliče CLR (common language runtime) (pač metoda main() je v .NET-u defenirana kot vstopna točka v program).

Ti si zadevo narobe zastavil.
Ponavadi imaš v metodi Main() nekaj takega:

Application.Run ( new ime_classa() );

kjer je ime_classa class ki hočeš da se ob zagonu programa konstruktira (vsaj v windows aplikacija je tako), v dos appih pa ponavadi imaš en razred samo zato da je v njem Main() in v Main() skonstruktiraš nek drug razred :

En tak bl glup primer:









Koda:

using System;

public class Indexers
{
public int a, b, c, d;
public Indexers()
{
a = 312;
b = 42342;
c = 31;
d = 6565;
}
public int this[int index]
{
set
{
if ( index == 0 ) this.a = value;
else if ( index == 1 ) this.b = value;
else if ( index == 2 ) this.c = value;
else if ( index == 3 ) this.d = value;
}
get
{
if ( index == 0 ) return this.a;
else if ( index == 1 ) return this.b;
else if ( index == 2 ) return this.c;
else if ( index == 3 ) return this.d;
else return 0;
}
}
}

public class IndexersTest
{
public static void Main ()
{
Indexers ena = new Indexers();
Console.WriteLine ( ena[0] + " " + ena[1] + " " + ena[2] + " " + ena[3] + " " + ena[4] );
ena[0] = 313;
ena[1] = 1;
ena[2] = 4242;
ena[3] = -31;
ena[4] = 42;
Console.WriteLine ( ena[0] + " " + ena[1] + " " + ena[2] + " " + ena[3] + " " + ena[4] );
Console.Read();
}
}

Da tukaj še jaz pristavim svoje (čeprav, je bilo že vse nekako pojasnjeno) ...

Razlika med golo funkcijo in statično member funkcijo - je kar velika, tudi v C++. Zato, ker jezik podpira metode, ki niso vezane na instanco objekta (statične metode), ni nič manj OO.

Statične member funkcije imajo dostop do privatnih memberjev, medtem, ko "gole" funkcije takšnega dostopa nimajo (razen, če jih explicitno v razredu deklariramo kot "prijatelje" (friends)).








Koda:

class SomeObject {
private:
int privateMember;
public:
static void doSomething(SomeObject& instance) {
privateMember = 123; // OK.
}
};

void doSomething(SomeObject& instance) {
instance.privateMember = 123; // NAPAKA!!!
}



C# je korak dlje. Dovoljuje uporabo t.i. statičnih konstruktorjev, ki omogočajo, kaj pa drugega, statično inicializacijo.








Koda:

class Application {
private static int staticMember
// statični konstruktor
static Application() {
staticMember = 123;
Console.WriteLine("statična inicializacija");
}
static void Main(string[] args) {
Console.WriteLine("tole se izpiše po statični inicializaciji ...");
}
}


C++ varianta statične inicializacije je veliko manj fleksibilna (in nerodna):








Koda:

class Application {
int staticMember;
public:
static void main(...) {
}
};

// statična inicializacija (kaj več kot to postane problem ...)
// - ni statičnih konstruktorjev
int Application::staticMember = 123;



Statične metode imajo svojo uporabnost, saj operirajo na nivoju razreda - za razliko od dinamičnih, na instanco objekta vezanih metod. NET CLR naredi preprosto tole, ko zažene applikacijo:








Koda:

// aplikacijska koda
class MyEntryPoint {
public static void Main(string[] args) {
....
}
}
// .NET CLR, jo pokliče takole:
MyEntryPoint.Main(...)


(Vstopna točka programa je samo *ena*, torej je bila izbira statične metode, v tem kontekstu, najbolj smiselna rešitev.)

... kar je pa popolnoma enaka zadeva kot npr.:








Koda:

// Math je razred, Sin pa je njegova statična metoda
// nikoli ne instanciramo Math objekta.
double x = Math.Sin(1.0);
// isto z razredom Console ...
Console.WriteLine("OO");
// nikoli ti ni potrebno ustvariti Console objekta


in to vsi smatramo kot popolnoma ok, z vidika OO. Tako, btw. Java uporablja enako metodo vstopne točke kot C#. Primer:








Koda:

public class HelloWorldApp {
public static void main(String arg[]) {
System.out.println("Hello World!");
}
}



p.s.: In še to. Class-ov se ne da kreirat!!! Class in objekt nista ista pojma. Lahko bi rekli, da "razred" je *pojem*, "objekt" pa je *stvar*, ki ustrezu temu pojmu.








Koda:

// "pojem" (razred) objekta Stvar
class Stvar {
....
}

// 1000 instanc objektov, ki ustrezajo "pojmu" (razredu) Stvar
for (int i = 0; i < 1000; i++) {
instance[i] = new Stvar();
}
// razred Stvar je pa še vedno le en, čeprav je instanc, ki mu pripadajo, mnogo.
