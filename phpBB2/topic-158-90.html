Koda:

// Find which lights to enable:

n = 1; // steps out from center to search
nlights = 0;

nlights = FindLights( i,j, lightind, BINSZ );

// now set the select lights "on" to render the scene! =)

///////////////////////////////////////////
// Now enable those lights that were found
for( cnt=0; cnt < nlights && cnt < 8; cnt++ )
{
// Need to SetLight() for each light as their positions are
// always changing
pd3dDevice->SetLight( cnt, & ( m_pLightManager->m_Lights[ lightind[cnt] ] ) );
pd3dDevice->LightEnable( cnt, TRUE );
}
// Disable any that aren't used:
for( cnt=nlights; cnt < 8; cnt++ )
{
pd3dDevice->LightEnable( cnt, FALSE );
}

// Override the last light to make light 8 directional
pd3dDevice->SetLight( 7, & m_pLightManager->m_StaticLight );
pd3dDevice->LightEnable( 7, TRUE );

///////////////////////////////////////////////////////
// Now draw that section of geometry under the lights

O nekem takem nacinu sem razmisljal za School Tournament, kjer bos v editorju postavil luci kakor bos hotel in mora pac stvar bit vsakic drugac. Vendar se mi zdi, da z vsako postavljeno lucjo povecas cas izrisa, tko da je velika razlika med 1, 2 al pa recimo 8 lucmi. Poglej si 3D Mark, kjer testira izris high poly count vrtiljaka z razl. stevilom luci.

Tako da zdaj nekaj razmisljam, da bom ali
- 1. zapeku svetlobo v vertexe, kar naj bi bilo zelo hitro in lepo za videt pri dost majhnih trikotnikih (recimo stranica 1m).
- 2. uporabu light mape, kjer lahko poleg svetlobe uracunas se sence. Sam prvo je treba naredit podporo za multitexturing, en raytracer ki ti izdela lightmape itd. Ker pa hocem imet bl mejhne fajle ne bi rad da je treba userjem posiljat velike pakete sam zarad razlicnih sol, tko da bom verjetno izbral 1. moznost.
