Class (razred) je osnovni gradnik objektno-orientiranega programiranja. Kot verjetno veš (ali pa tudi ne ) C++ podpira objektni pristop do programiranja. Medtem, ko imaš v C++ na razpolago nekatere že vgrajene podatkovne tipe (int, char, float, ...), ti razred omogoča izgradnjo svojega podatkovnega tipa.

En zelo šolski primer razreda:









Koda:

// Deklaracija novega podatkovnega tipa CLucka:
class CLucka {
private:
  int prizgana; // Deklaracija spremenljivke, ki pripada razredu.

public:
  // To je konstruktor. Njegova vloga je ta,
  // da inicializira spremenljivke znotraj objekta
  // na začetno vrednost. V nasem primeru konstruktor
  // postavi naso spremenljivko prizgana na vrednost 0.
  CLucka() : prizgana(0) {}
 
  // To je destruktor. Njegova vloga naj ostane skrivnost
  // do naslednjic.
  ~CLucka() {}

  // Metoda Prizgi inicializira spremenljivko "prizgana" na 1
  // (lucka gori)
  void Prizgi() {
    prizgana = 1;
  }
  // Guess what? :)
  void Ugasni() {
    prizgana = 0;
  }
};

Sedaj poglejmo kako se razred rabi:









Koda:


// S tem ukazom zgeneriramo novo objekt tipa CLucka.
CLucka stat_lucka;

// Prizgimo lucko:
stat_lucka.Prizgi();

// Izkljucimo lucko:
stat_lucka.Ugasni();











Koda:

// S tem ukazom pa iz razreda zgeneriramo kazalec na objekt, kateremu se dinamično dodeli zadostna količina pomnilnika.
CLucka* din_lucka = new CLucka();

// Prizgimo lucko:
din_lucka->Prizgi();

// Izkljucimo lucko:
din_lucka->Ugasni();

// Pobrisemo objekt (sprostimo pomnilnik)
delete din_lucka;



V zgornji kodi smo ustvarili dvakrat isti objekt.

V prvem primeru smo dobili statično spremenljivko (stat_lucka), kar pomeni, da se je takoj ob zagonu programa rezerviral prostor zanjo.

V drugem primeru pa smo dinamično zgradili objekt. Pomnilnik smo dimamično zasegli ob klicu "new" operatorja pri ukazu:








Koda:
CLucka* din_lucka = new CLucka();


Ker smo objekt zgradili sami, moramo poskrbeti, da ga tudi pobrišemo. To storimo z ukazom "delete".

Ok, pa nadaljujmo.

Oglejmo si princip ti. "dedovanja".

To je takrat, ko ti prijazni starši pred odhodom v boljši sv... ah... ne... to ni to... nekaj drugega bo Malo resnosti prosim.

Ok, poglejmo si dedovanje na preprostem primeru (Zaradi preglednosti sem izpustil konstruktorje in destruktorje razredov):








Koda:

class A {
private:
  // tukaj so generične spremenljivke, ki so skupne vsem objektom tipa A
  int s1;

public:
  // tukaj so generične metode, ki so skupne vsem objektom tipa A
  void M1() { ... }
  void M2() { ... }
};

class B : public A {
private:
  // tukaj so spremenljivke, ki so specifične le za objekt tipa B
  int s2;

public:
  void M3() { ... } // metode značilne le za objekt tipa B
};


Kaj se tukaj dogaja? Razred B je "podedoval" spremenljivke in metode razreda A. Lahko tudi rečemo, da smo razred B razširili z razredom A. Poglejmo kako izgleda tak razširjen objekt:








Koda:

B b; // ustvarimo nov objekt tipa B
b.M3(); // kličemo metodo objekta B.
b.M1(); // kličemo metodo, ki smo jo podedovali iz razreda A
b.M2(); // kličemo metodo, ki smo jo podedovali iz razreda A


To je podobno, kot da bi napisali sledeče:








Koda:

class B {
private:
  int s1;
  int s2;

public:
  void M1() { ... }
  void M2() { ... }
  void M3() { ... }
};



Zakaj dedovanje? Zaradi enega primarnih prednosti OOP (objektno orientiranega programiranja): ponovna uporaba izvorne kode (ang. reusability). Obstaja kak drugi slovenski termin za "reusability"? V starševski razred (ang. parent) vpišemo kodo, ki je skupna večim drugim razredom in ki to kodo podedujejo. Namesto, da bi kodo copy-pastali po vsakem razredu posebej, preprosto vsak razred razširimo s staršem. Jasno?

Sklepam, da uporabljaš Visual C++ verzije 6, ali imaš .NET? Tale izvorna koda ima le .sln datoteko, ki jo zna odpret le .NET verzija C++ kompajlerja.

Kot prvo potrebuješ SDL source, ki ga odpakiraš nekam na disk:
http://www.libsdl.org/release/SDL-devel-1.2.5a-VC6.zip

Ker je sdl.dll že vključen v projekt, ti tega ni treba downloadat. (stvar pa dobiš tukaj: http://www.libsdl.org/release/SDL-1.2.5a-win32.zip)

1.) Predpostavljam, da imaš VC++ .NET.

Zaženi datoteko FirstEngine.sln -> odprl se ti bo projekt znotraj visual studia. Sedaj moraš nastavit poti do include (.h) in library (.lib) datotek, ki se nahajajo znotraj odpakirane "SDL-devel-1.2.5a-VC6.zip" datoteke.

V meniju "Tools" izberi "Options..." in odprlo se bo okno za nastavitev poti:
Dodaš pot do .lib datotek...

... in pot do .h datotek:

OK, zapri okno.

V "Solution Explorerju" odtrani sdlmain.lib in sdl.lib, ker je to nepotrebno. Po odstranitvi naj bi okno izgledalo takole:


Stvar skompajliraj in mini-game naj bi se zagnal brez težav. Če igro poganjaš iz explorerja direktno, se prepričaj, da je datoteka sgd.dll v istem direktoriju kot exe.

2.) Za starejše verzije VC++ je postopek podoben. Dodaš poti do dirrektorijev lib in include, pobrišeš sdlmain.lib in sdl.lib iz projekta (ne iz diska! ) in stvar buildaš in zaženeš.

Ker nimam starejše verzije VC++ inštalirane boš moral pred vsem tem naresti nov prazen win32 project in vanj dodati vse datoteke iz direktorija FirstEngine/Src.
