VKJMZ (AFAIK) v q3 ni ne B-t-F niti F-t-B sortiranja (ok, prepričan sem samo za F-t-B). Kar skrbi za sortiranje faceov so materiali (poglej si materialflags.h --> SORT_ enum v v2src). Glede na to se potem sortirajo.

In če me spomin ne vara, boš moral za uspešno dosežen cilj poseči po materialih (shaderjih, da ne bo zmede). in njihovem sortvalue-u.

Nisem povsem prepričan, vendar če nekako določiš vsakemu face-u sortvalue iz pripadajočega materiala, potem lahko narediš sort nekako takole:









Koda:

int compare_faces(const void *a, const void *b)
{
   return ((face_t*)a)->sort_value - ((face_t*)b)->sort_value;
}

...
qsort((void*)face_list, r_numfaces, sizeof(face_t), compare_faces);

...



Tako, tvoji face-i bi morali potemtakem biti sortirani glede na sort_value vrednosti (ki smo jih pobrali iz materialov).

Tako da pri že narejenih mapih imaš že pravilno določene SORT_ vrednosti, po defaultu pa je to SORT_NORMAL (no shit).

P.S.: Tole je bilo bolj tako-tako, materiali so v resnici shaderji, le poimenovanje je nekoliko drugačno (I'm doing on them, not you guys!).
P.P.S.: Nisem prepričan če tole sploh deluje, oz. če je to tisto kar hočeš
P.P.P.S.: Če se ne motim je tole F-t-B renderiranje.

Koda:
void RX_drawbsp_b2f(int n)
{
   if (n < 0)
   {
      RX_DLeaf(n);
      return;
   }
   tBSPNode_t* node = &nodes[n];
   tBSPPlane_t* plane = &planes[node->plane];
   float side = (x * plane->vNormal[0]) + (y * plane->vNormal[2]) + (z * plane->vNormal[1]) - (plane->d);
   if ((side < 0) ^ (gugi))
   {
      RX_drawbsp_b2f(node->front);
      RX_drawbsp_b2f(node->back);
   } else {
      RX_drawbsp_b2f(node->back);
      RX_drawbsp_b2f(node->front);
   }
}
