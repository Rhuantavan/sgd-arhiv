tukaj imaš psevdo kodo za Bresenhamov algoritem za rasterizacijo premice.









Koda:

function line(x0, x1, y0, y1)
boolean steep := abs(y1 - y0) > abs(x1 - x0)
if steep then
swap(x0, y0)
swap(x1, y1)
if x0 > x1 then
swap(x0, x1)
swap(y0, y1)
int deltax := x1 - x0
int deltay := abs(y1 - y0)
int error := 0
int y := y0
if y0 < y1 then ystep := 1 else ystep := -1
for x from x0 to x1
if steep then plot(y,x) else plot(x,y)
error := error + deltay
if 2×error &#8805; deltax
y := y + ystep
error := error - deltax



Če nočeš delati z tem pa izračunaj kot med začetno in ciljno točko (to lahko narediš recimo z vektorji, ali z preprosto geometrijo). Iz tega kota pa potem izračunaj DX in DY, ki ju prištevaš trenutni poziciji projektila.

hmmm, sn mal premislil. Če ti daš tam ABS, rabiš posebej preverjat kam je kot obrnjen, oz. v katerem kvadrantu se nahaja. Če ne daš absolutno, pa je to preverjanje odveč, ker je ena stranica kota vedno ista, tako kot v enotski krožnici za kotne funkcije. Tako nimaš vedno trikotnika, imaš pa eno stranico vendo znano, pozicija druge pa je relativna na prvo.

Z drugimi besedami: če uporabljaš abs, dobiš vedno kote manjše od 90, kar kasneje pomeni, da dobiš tako DX in DY pozitiven, ne glede nato ali ju moraš odšteti ali prišteti. Sam moraš ugotoviti ali ju boš prištel ali odštel. Če pa abs izpustiš, jih lahko vedno samo prištevaš, saj bosta vrednosti, če bi ju bilo treba odštevati, negativni.

Glede knjižnic:
meni se zdi zelo zanimivo, da vsaka funkcija, ki sprejema kote ali z njimi dela, uporablja drugačen format. Veliko je sploh takšnih, ki nimajo nobene veze z radiani ali stopinjami (recimo allegro ima 64 za 90°).
