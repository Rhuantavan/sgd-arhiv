Razlike med programskimi jeziki so ogromne, sploh za zacetnika. Ce bi rad delal z DirectX ti najbolj priporocam C#. Najhitreje bos dobil rezultate. Jaz sicer se nisem presedlal, ampak moras drugace razmisljati. Recimo XNA je zastonj in gre za nekak "C# game developer edition". Namesto da se sam zajebavas z grafiko, meshi, texutrami je za tebe ze vse koncano. Seveda je zanimivo, da vidis kako to deluje (C++) ampak po drugi strani ogromno casa potratis pa se vedno nimas rezultatov. C C# ti je vse to prisparano, ker je ze nekdo v naprej za tebe mislil, in se lahko koncentriras le na igro.

S c/c++ je tezko zaceti, ker C v osnovi ponuja zelo malo za delo z grafiko, poleg tega pa te pri hello world programckih hitro mine. Sploh pa ce te zanima kako dela grafika v Winsih (native, tu ni misljeno OPENGL ali DIRECTX) bos znorel zraven. V C# pa je ze vse za tebe pripravljeno. Tako, da se mi zdi da si Game Studio Express dol potegnes pa zacnes delati v C# kot najboljsa resitev.

Pa se nekaj. Med C in C++ je velika razlika. Stos je v tem, da C++ podpira vse kar podpira C, medtem ko C ne podpira nic kar podpira C++.

npr.:








Koda:

void main()
{
char ime[80];
printf("Vnesi ime:");
scanf("%s", ime);
int starost;
printf("Vnesi starost");
scanf("%d", &starost);
}



To je cisti C++ program, ceprav se folk tega sploh ne zaveda, ker jim C++ vse poenostavi. Kje tici zajec? V starosti. V Cju lahko definiras spremenljivke samo v zacetku bloka in ne kjerkoli po programu. To je C++ feature. Polno je se takih malenoksti. Dan danes folk v vecnini pise v C++ in ne v Cju. Ali compiler ti to skirje, da niti ne opazis.

S C# lahko zacnes delati igrice nemudoma, pa se vedno bos moral programirati. Brez strahu. Najvec se naucis ce zacnes klikati in vdihovati kodo. To v C++ bolj tezko ampak s C# pa gre zelo hitro!

Q: Can I use this call-a-DLL approach to write Xbox 360 XNA Game Studio Express games for other non-C# CLR languages like Iron Python or Visual Basic?

A: Unfortunately no, not for those two specific languages. (Sorry!) The reason is that the Xbox 360 version of the XNA GSE CLR is based on the .NET Compact Framework 2.0. This is a problem for Iron Python and Visual Basic because those particular languages rely on CLR features that are not present in the .NET Compact Framework 2.0. Therefore you will get a runtime error when you try and run your Iron Python or Visual Basic code on the 360. It's possible that future versions of either the languages or the Xbox 360 GSE runtime will fix this problem. (But don't hold your breath -- nobody has promised anything in these areas.
