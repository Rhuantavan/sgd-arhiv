Nekaj nasvetov za v bodoce:

Opazil sem, da v SQL-u na veliko uporabljas LIKE operator, kjer sploh ni potreben. LIKE se uporablja, ce nimas tocno dolocene vrednosti, ki jo zelis primerjati, oz. vsebuje posebne znake za zamenjavo enega ali vec znakov (_, %), je pa vsekakor pocasnejsi kot navadna primerjalni operator =.

Naslednja stvar pa se tice nacina, kako prides do primarnega kljuca dolocenega zapisa. Tako kot si se zraven spravil, sicer deluje, a je pocasi in ne bo delovalo v vseh primerih (s select stavkom, kjer navedes vse nekljucne atribute). Ta nacin ne bo deloval, ko se lahko nekljucni atributi ponovijo v vec zapisih (zato pa se racno uporablja kljuc). V tem primeru bos kot rezultat dobil vec ID-jev.
Stvar resis ali z uporabo sekvenc (sequence). Sicer mislim, da Access ne podpira sekvenc (najbrz imas kljuc nastavljen kot autonumber), ti bo pa prislo prav, ko bos kdaj delal s 'pravo' podatkovno bazo , tako da jih lahko malo nastudiras.
Druga moznost pa je programska in sicer lasten ID provider. Napises si nek razred, ki bo hranil vrednosti trenutnih kljucev vseh tabel (npr. hashtable, dictionary). Torej, ob zagonu tvoje aplikacije se bo inicializiral tale tvoj ID provider in se napolnih s trenutnimi vrednostmi:









Koda:

id = SELECT MAX(ID) FROM TABELA1;
if (id == NULL)
id = 0;
idProviderTable['TABELA1'] = id;
id = SELECT MAX(ID) FROM TABELA2;
if (id == NULL)
id = 0;
idProviderTable['TABELA2'] = id;
.
.
.



Nato pa zmeraj ko bos vnesel nov zapis v doloceno tabelo, poklices svoj ID provider, ki ti vrne naslednji kluc za to tabelo:









Koda:

int getNextIdFor(String pTableName) {
int id = idProviderTable[pTableName];

id++;
idProviderTable[pTableName] = id;
return id;
}



Nato pa lahko veselo vneses nov zapis v svojo tabelo in v vse tabele, ki se nanjo navezujejo preko tujih kljucev:









Koda:

addressId = idProvider.getNextIdFor('ADDRESS');
INSERT INTO ADDRESS (ID, STREET, ...) VALUES (addressId, 'fdsfsdfds', ...)
potnikId = idProvider.getNextIdFor('POTNIK');
INSERT INTO POTNIK (ID, ADDRESS_ID, ...) VALUES (potnikId, addressId, ...)



V primeru, da bos uporabil svoj ID provider, lahko nastavis kot tipe primarnih kljucev vseh tabel INTEGER.
