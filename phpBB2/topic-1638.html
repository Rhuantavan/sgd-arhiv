}

try {
Score.iniArea();

this.add(scor);
}

if(source==clear){

try {
Score.delete();
Score.ustvari();
} catch (IOException ex) { }

}

if(source==about){

if(source==quit){

class Keys implements KeyListener{
public void keyPressed(KeyEvent e) {
int key=e.getKeyCode();

if((key==KeyEvent.VK_LEFT)&&(!Snake.right)){
Snake.left=true;
Snake.down=false;
Snake.up=false;
}
if((key==KeyEvent.VK_RIGHT)&&(!Snake.left)){
Snake.right=true;
Snake.down=false;
Snake.up=false;
}
if((key==KeyEvent.VK_UP)&&(!Snake.down)){
Snake.up=true;
Snake.left=false;
Snake.right=false;

}
if((key==KeyEvent.VK_DOWN)&&(!Snake.up)){
Snake.down=true;
Snake.left=false;

}

Evente naj vsekakor frame lovi. Če evente prejema panel, mora imeti tisti panel focus, kar pa zgubi ko klikaš ostale elemente. Kdaj točno ga pa dobi nazaj je pa težko reči. Morda ga niti ne dobi, če klikneš nanj. Če hočeš da bo nek objekt zares imel focus, kličeš njegovo metodo requestFocusInWindow(), ta ti mora vrniti true, potem pa moraš počakati da objekt prejme FOCUS_GAINED dogodek.

Za iskanje napake pa ne vem kaj ti naj svetujem. Najprostejši način, a hkrati tudi časovno potraten, je da postaviš nekaj izpisov v kodo, potem pa opazuješ kaj se dogaja. Da boš vedel kateri deli se dejansko izvedejo, in kateri ne. Za ta primer jih nekaj postaviš v lovljenje eventov, potem pa greš po verigi procedur naprej. Tako boš videl kje se ti ustavi. Verjetno so tudi kake boljše metode, se morda malo pozanimaš o tem.
