C# Properties

Avtor: CWIZO
Objavljeno: 01.03.2004, ob 13:47:36.


Properites so v C# neke vrste "napredne" spremenljivke (del razreda), ki nam omogočajo večjo kontrolo nad tem kaj se shranjuje v spremenljivki. V samem property-u se vrednost ne shrani, zato moramo imeti v razredu (class) neko "backend" spremenljivko, ki nosi dejansko vrednost, katero se nastavlja preko property-a. Preden nadaljujem in razložim zakaj so property-i sploh uporabni, si poglejte tole splošno obliko property-a:

acces-modifier return-type name
{
    get; set;
}

Prve vrstice najbrž ni potrebno razlagati. Kaj pa sta get in set? To sta ključni besedi in znotraj njunih dveh blokov nastavljamo oziroma vračamo vrednosti. Znotraj bloka get napišemo kodo, ki klicočemu objektu (naprimer: string nekaj = nasObjekt.NasProperty;) vrne vrednost spremenljivke (pač tiste ki si jo sami izberemo), v set bloku pa napišemo kodo, ki bo recimo preverila če je vrednost, ki jo nek objekt hoče nastaviti (naprimer: nasObjekt.NasProperty = "nekaj") v pravilnem formatu.
Mogoeč vam je sedaj že jasno zakaj so property-i uporabni. Namreč, do navadne spremenljivke (naprimer: public int MyInit;) lahko dostopamo kakorkoli želimo in vanjo lahko shranimo kakršnokoli vrednost tipa System.Init32. Kaj pa če hočemo zagotoviti da je vrednost, ki jo dodelimo tej spremenljivki na določenem intervalu? Lahko bi sicer spremenljivko označili kot private in potem ustvarili metodo SetMyInit ( init var ), ampak to je nerodno (tako se to dela naprimer v C++ -u, ki propertyev ne pozna). In tukaj uspešno uporabimo property-e. Da ne bom preveč dolgovezil in vas še bolj zmedel, si uporabo poglejmo na preprostem zgledu. Da bodo stvari preproste je tole navadni konzolni program.

01: using System;
02: public class PropertiesTest
03: {
04:     private int myInt; // privatna spremenljivka tako da do nje lahko dostopamo le znotraj razreda
05:
06:     public int MyInt
07:     {
08:         get
09:         {
10:             return this.myInt; // objektu, ki je zahteval vrednost MyInt, vrnemo vrednost spremenljivke myInt
11:         }
12:         set
13:         {
14:             if ( ( value > 10 ) & ( value < 100 ) ) // spremembo vrednosti bomo dovolili le če je vrednost med 10 in 100
15:             myInt = value;
16:         }
17:     }
18: }
19:
20: class Program
21: {
22:     static void Main(string[] args)
23:     {
24:         PropertyTest obj = new PropertyTest ();
25:         obj.MyInt = 55; // preko property-a dodelimo vrednost spremenljivki myInt
26:         Console.WriteLine ( "MyInt je {0}", obj.MyInt );
27:
28:         obj.MyInt = 150; // ker smo dodelili preveliko vrednost se vrednost spremenljivke myInt ne spremeni
29:         Console.WriteLine ( "MyInt je {0}", obj.MyInt );
30:
31:         Console.Read ();
32:     }
33: }

Get bloka ni treba razlagati saj komentar razloži vse. Najbrž ste v set bloku opazili ključno bčsčdo valuč. V tem objektu se "skriva" vrednost, ki jo klicoči objekt poda property-u. V zgornjem primeru v vrstici 24, je vrednost, ki jo bo dobila spremenljivka value enaka 55, v vrstici 27 pa 150.
Kot vidite sem pogledal če se vrednost value nahaja na intervalu (10, 100) in če se sem, potem to vrednost dodelil myInt, drugače pa pče ne.
To je zelo preprost primer, ki pa nazorno pokaže kako lahko kontroliramo kaj se bo shranilo v neko spremenljivko znotraj razreda.

še ena koristna lastnost propertijev je to, da lahko property nastavimo kot: "read-onyl" ali "write-only". Če prevedem; property lahko nastavimo tako, da preko property-a samo nastavimo vrednost, ne moremo je pa prebrati oz. jo lahko samo preberemo, ne moremo je pa zapisati. To storimo tako da preprosto ne vključimo enega izmed blokov set ali get. Če naprimer hočemo "read-only" property, vključimo samo get blok ne pa tudi set. Primer:

public int ReadOnly // samo za branje
{
    get
    {
        return NekaSpremenljivka;
    }
}

public int WriteOnly
{
    set
    {
        NekaSpremenljivka = value;
    }
}

Tako, to je kar se property-ev tiče vse, samo še povem, da property-ev ne morem preobložiti (overload-ti). Naj samo še omenim da v C#-u obstaja še ena podobna "struktura", ki se ji reče Indexer in deluje podobno kot property (delita si get in set bloka). Indexer-je bom opisal v enem od naslednjih člankov.
